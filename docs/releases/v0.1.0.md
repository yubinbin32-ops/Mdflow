# mdflow v0.1.0 — Architecture that stays visible

![mdflow](../../topic-logo-mark-black.png)

> A native macOS workspace for AI-assisted software architecture, Plans, and evidence-backed delivery.

## The moment

Most AI development tools can show you files. mdflow shows you the system those files are meant to become.

This first release turns architecture into a living, queryable surface: Blocks for responsibilities, Links for relationships, Chains for reusable paths, Plans for ordered work, and checkpoints for evidence.

## What is new

- **Block-level Plans** — direct Block work is visible even when a Block belongs to no Chain.
- **Demand-driven checkpoints** — architecture discovery does not create verification noise; requirements and Plans create the checks that matter.
- **Markdown-first MCP context** — concise, structured Markdown by default; full JSON only when explicitly requested.
- **Scoped rules** — project, lens, Chain, and repository rules are indexed by scope and stay out of the Canvas.
- **Stable Canvas lenses** — checkbox changes animate the projection without moving unrelated cards or refitting the camera.
- **Natural Plan detail** — Direct Block Work, ChainScope paths, dependencies, evidence, and acceptance appear in one inspector.
- **Git-aware graph storage** — checkout replacement detection keeps the App and MCP aligned with the committed graph.

## The proof sequence

```text
Requirement → Blocks/Links → Chains → Plan → Checkpoints → Evidence → Release
```

The release was checked in the same order:

1. MCP regression: **41/41 passed**.
2. Desktop regression: **30/30 Swift tests passed**.
3. Large graph: **300 Blocks / 599 Links / 6 Chains** with deterministic orthogonal routing and endurance evidence.
4. Context parity: **13/13 facts**, **0 errors**, **0 rework proxy turns**, **29.4188% fewer tokens** for the mdflow projection (2,344 vs 3,321 tokens).
5. Package verification: strict codesign, private-data audit, and a 13-file release manifest.

## Install

Download `mdflow-0.1.0-macos.zip`, expand it, and move `mdflow.app` to `/Applications`.

Verify the archive with:

```sh
shasum -a 256 -c SHA256SUMS
```

The release archive is produced by `npm run release:assets`. A local build is ad-hoc signed; `npm run release:upload` refuses it until Developer ID signing, notarization, and Gatekeeper acceptance are complete.

## The promise

mdflow gives an AI a shorter path to the truth:

- coverage before prose,
- direct work before inferred ownership,
- scoped rules before repeated policy text,
- evidence before completion claims.

Open [the launch story](../launch.md) for the full product walkthrough.

## Known release boundary

This release does not hide its boundary. The local artifact can be verified and installed, while public Developer ID distribution remains an environment-specific release step. The package must not be described as notarized until `release:notarize` and Gatekeeper verification have completed.
