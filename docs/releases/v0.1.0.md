# mdflow v0.1.0

## Architecture memory for coding agents

mdflow connects architecture, implementation work, and verification in one project graph. The release is deliberately small in its promise:

```text
context → plan → edit → verify → handoff
```

The macOS app is the readable surface. The MCP server is the semantic write path. Markdown is the default AI-facing projection; structured JSON is available only when requested.

## What is in this release

- **Direct Block Plans** — a Plan names the Blocks it changes, even when they are not in a Chain.
- **Demand-driven checkpoints** — creating an architecture Block does not create a verification obligation. Requirements, Plan work, gates, or explicit verification do.
- **Chain integration gates** — Chains describe ordered paths and integration evidence; they do not own or manage Blocks.
- **Scoped rules** — project, lens, Chain, and repository rules are indexed by scope, kept out of the Canvas, and expanded only when relevant.
- **Markdown-first MCP** — compact context and receipts by default; opt in to structured JSON with `includeStructured=true`.
- **Coverage visibility** — context and Plan detail expose standalone, unplanned, checkpoint-free, required-missing, and failed states.
- **Stable Canvas projection** — lens checkboxes animate only the visible delta, preserve unrelated positions, and respect reduced-motion settings.
- **Plan detail** — Direct Block Work, Chain paths, dependency gates, evidence, and final acceptance are visible in one inspector.
- **Git-aware graph storage** — the canonical SQLite graph is tracked with the project and reopens after checkout replacement.

## Install one way

### Local candidate

```sh
npm run release:assets
```

Then verify the generated archive before opening it:

```sh
shasum -a 256 -c dist/release/SHA256SUMS
```

Move `mdflow.app` to `/Applications`. The local artifact is ad-hoc signed. It must not be described as notarized until Developer ID signing, notarization, and Gatekeeper assessment have completed.

### Contributor checkout

```sh
npm install
npm test
swift test --package-path apps/desktop
```

Choose the contributor path when changing mdflow itself; choose the packaged path when testing the app artifact. Keeping these paths separate makes release failures diagnosable.

## Known boundary

This is a local release candidate, not the public upload. The isolated local Codex lifecycle is verified; external-machine review, Developer ID/notarization, GitHub release upload, and the final external LLM experiment remain open gates. The upload command refuses an ad-hoc package by design.
